Agent Evaluation Platform

This webpage demonstrates Synth-EHR, a platform for evaluating medical AI agents. In this tutorial, you can create agent tools for accessing synthetic health records, customize task workflows and agent instructions, inject errors into patient records, run an AI agent, and visualize its accuracy, workflow adherence, and resource usage. We will configure these settings for a nuanced clinical task: identifying patients whose records contain evidence of type 2 diabetes.

If this is your first visit, I recommend loading the example run. It provides a clearer picture of how the settings fit together and how adjustments affect agent performance. Otherwise, customize each step to your liking. See whether you can configure the inputs to improve agent performance, limit the amount of irrelevant data retrieved, or even create situations in which the agent does not perform well.

Task: Identify patients with evidence of type 2 diabetes

For this task, we follow a seven-step sequence:

  1. Use a sample of realistic, pregenerated patients, some of whom have diabetes and some of whom do not.
  2. Design the tools an AI agent can use to access patient data.
  3. Provide task instructions and, optionally, define an ideal sequence of tool calls against which to compare the agent's behavior.
  4. Inject noise into the data presented to the agent by manipulating relevant laboratory results and censoring a related diagnosis. Along with tool design, this projects a complete patient record into an imperfect electronic representation.
  5. Verify how the noise affected the patient data so that we can interpret agent performance accurately.
  6. Run the agent independently for each patient.
  7. Analyze the results.

Step 2 · Design agent tools

Design the tools the agent can use to request data from our patient records. Each tool needs a name, a description, a return type, and a key.

Entities and Fields Entities refer to categories of patient data such as medications, conditions, immunizations, and more. Fields are attributes within an entity. For example, the 'allergies' entity includes fields such as reaction and reaction severity.
Returning Multiple Entities Creating tools that return multiple entities (e.g. 'Medications' and 'Conditions') can improve agent reasoning in some cases, but can also result in an agent accessing a plethora of irrelevant data.

Step 4 · Define noise

This step recreates the layer of obscurity that exists between an actual patient and their electronic health record. The noise defined here will be applied to the version of the patient's record that our agent accesses, not the original patient records we generated in step 1.

Reproducible by design For this tutorial, sources of noise with any random element are standardized to a specific seed. This means that a particular source of noise will have the same effect on a specific patient's health record on any run where the noise source is used.
